Two more variables than the prompt named: `SF_WRITE_INTERVAL_SECONDS` (worker schedule, 0 = off) and `SF_WRITE_FAKE_FAIL_FIRST` (fake only: refuse each opportunity's first update, so the e2e can retry a failed row).
- **Settings (provisional, off):** `sf_writeback_enabled` false, `sf_writeback_mode` dry_run, `sf_writeback_map`, `sf_writeback_stage_regression` skip, `sf_writeback_max_attempts` 5, plus **`sf_writeback_retry_minutes`** [1, 5, 30, 120, 360] (the prompt asked for the delays to be settings; this is that setting). `sf_writeback_map` is `{ entries, stageMap, stageRank }`: each entry `{ event, enabled, sfObject, sfField, value: { source, key? }, closing: [source keys], reopens }`. **Deviation:** the `closing` flag is a list of the outcome (or stage) keys whose value closes the opportunity (seed `["lost", "expired"]`) rather than one boolean, because one entry covers every outcome. **`stageRank`** (Salesforce stage → rank) was added for the regression check: the org's stage list (`sf_stage_map.sort`) mixes two stage sets and is not a pipeline order; closed stages rank last, Closed Won above Closed Lost.
- **Allow-list check of the map.** The domain can't import the connector, so the settings console's own parser checks shape and bans figure names; the API adds the allow-list check through a new `AdminConfigService` option `settingCheck` (two lines in `adminConfig.ts`), which also refuses `sf_writeback_mode = live` where there is no write connection.
- **Enqueue.** One call in `GateService.decide` after the notifications (`sfWriteback.onGateDecision`), one in `RequoteService.start` after the draft (`onRequoteStarted`). Everything runs in a **savepoint**, inserts use `ON CONFLICT (dedupe_key) DO NOTHING`, and any failure is logged and audited, never thrown: a configuration error cannot abort a decision. Dedupe key: quote id, event, value, gate decision id (or draft id; `once` for `quote_link`). `outcome_recorded` only at Customer Decision (G5). A closing write is inserted as `skipped` / `other_active_quote` when another non-closed quote or an open linked re-quote draft is on the opportunity (checked in the transaction and on the system pool, and again by the worker in the system context).
- **Re-quote, after review.** A closing row the re-quote supersedes **after a try** (attempts above 0: a timed-out try may have reached Salesforce) no longer makes the reopen `nothing_to_reopen`: the reopen is queued pending, and the worker sends it only if the stage it reads is that close (otherwise `nothing_to_reopen`, nothing written). In a **dry run** the re-quote supersedes the closing row its own expiry just recorded, so the outbox shows exactly what live would (a skipped close and a skipped reopen).
- **Re-quote.** The open-lapsed path records G5 "expired" first (queuing a pending closing write), then creates the draft: `onRequoteStarted` marks every still-pending closing write for the opportunity `skipped` / `other_active_quote` (audited with `supersededBy: requote_started`) and queues the reopen, which is `skipped` / `nothing_to_reopen` when QuoteFlow's last written stage on the opportunity was not closing. **Deviation:** the prompt says the reopen "supersedes" a pending close; the superseded closing row's reason is `other_active_quote` (the true reason: the opportunity is needed again), not `superseded` (kept for the worker's latest-value collapse).
- **Worker** `apps/api/src/jobs/sfWriteback.ts`, advisory lock `ADVISORY_LOCKS.sfWriteback` = 2_901_001 (one line in `packages/db/src/advisoryLock.ts`), each minute; per opportunity one transaction holding the rows' locks while sending; idle unless on, live and valid, with a writer. `confirmed_existing` rows end `sent` (a `response` note and the audit row say so). Final failure: in-app `sf_writeback.failed` to each active Admin, dedupe key `sf_writeback:<row id>` (new type in `notifications/events.ts`, email none).
- **Audit:** existing actions with entity `sf_writeback`: `create` (queued, or not queued with the reason), `update` (sent, skipped, failed, retry scheduled, Admin retry, Admin skip), `config_change` (switch, mode). Worker rows have `actor_id` null. No migration change to `audit_event_action_check`.

Reads `config.read`, changes `config.manage`; registry and `docs/security/route-inventory.md` updated. Skip is allowed on a failed **or pending** row (a row queued while live stays pending if the switch is turned off). The page no longer says "read-only toward Salesforce".
