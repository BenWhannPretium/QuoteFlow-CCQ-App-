## What the code does today (read 2026-11-18 at `f017ccc`; verify before relying on it)
- **Capital readiness** values: `not_required`, `pending`, `pre_approved`, `not_approved` (`packages/domain/src/pricing/record.ts` ~24-41, labels "Capital pending (budgetary)" etc.). Column `pricing_record.capital_readiness`, nullable; `EMPTY_PRICING_RECORD` has `null`.
- **How it is set today:** on a forward G2 decision with Engineering's capital needed, `apps/api/src/services/gateService.ts` ~664-718 sets `quote.capital_likely = true`, sends the Capital Management notice, writes a `capital_needed` activity event and upserts readiness from `app_setting.capital_readiness_on_outcome` (seed `{ 'G2:capital_required': 'pending' }`; that outcome was switched off by FB-17) falling back in code to `capitalNeededNow ? 'pending' : null`. When no capital is needed nothing is set, so the pricer must pick one.
- **Capital needed:** `engCapitalNeeded` (`packages/domain/src/engineering/capital-needed.ts` ~53-56) is true when the figure is above `app_setting.capital_needed_above_usd` (seed 0); a blank figure counts as needed. FB-19 sums the items' preliminary capital for the quote; check how `capitalNeed(...)` reads items.
- **The G3 rule that blocks "pending"** (`packages/domain/src/workflow/seeds/hybrid.ts` `PRICE_APPROVED` ~143-176): `present(capital_readiness)`; `readiness in (not_required, pre_approved, not_approved) OR capital_pending_justification present`; **and** `capital_likely = false OR readiness in (not_required, pre_approved)`. The last rule's label is "Capital is flagged likely: confirm capital readiness (not required or pre-approved)" (`workflow/requirement-labels.ts` ~69-70). So every capital quote must say "pre-approved" to advance, which is what the demo had to do.
- **"Not required" is refused** while Engineering says capital is needed (`pricing/record.ts` ~407-414; `QuotingTab.tsx` ~775 and ~793 disable the option). Keep this.
- **Payback:** `roi_required` is derived (`packages/domain/src/commercial/derived.ts` ~67-70) from `app_setting.roi_required_when` (seed `{ g2Outcomes: ['capital_required'], capitalLikely: true, fundingModels: ['CUSTOMER_FUNDED','ZERO_CER'] }`, `quoting-steps/index.ts` ~48-52). G3 needs `roi_required = false OR roi_model_on_file` (`hybrid.ts` `QUOTING_MODELS_ON_FILE` ~128-141). Because `capitalLikely: true`, every capital quote needs Finance's payback model. The steps' status logic is `quoting-steps/index.ts` ~312-358 ("Waiting on an earlier step").
- **Finance** is told (`quote.ready_for_roi`, roles in `ROI_OWNER_ROLES = ['Finance']`) only when a **costing** model is uploaded and payback is required (`apps/api/src/services/attachments.ts` ~837-874 `announceModel`; `notifications/recipients.ts` ~479-486). A payback upload tells the PricingLead (`quote.roi_uploaded`).
- **Lead review (pricing):** the assigned pricer submits with "Submit to pricing lead" (`LeadReviewPanel.tsx` `LeadReviewActions`, rendered at the **bottom** of the Quoting tab, `QuotingTab.tsx` ~125 / ~285; `POST /quotes/:quoteNumber/quoting/submit`). - **Quoting tab order** (`QuotingTab.tsx` ~83-146): ApprovalStatus, PricerAssignment, LeadReviewStatus, SectionLockLine, IntakeCommercialCard, QuoteItemsList (multi-item), EngineeringInputsCard ("From engineering": BOM link, two-step, pack-out; component in `EngineeringExtras.tsx` ~622-639), QuotingSteps ("Costing, payback and price approval"), then Warnings, **EngineeringSummary** (G2 decision and note, process, machine, plant, cavitation, cycle time, budgetary capital, technical concept, capacity evidence; ~387), PricingContextForQuote, PricingRecordCard, CapitalCard, History, PricingLeadActions.

## Build

### Part A. Capital readiness: "pending" is the normal state and can go ahead (N17-19, N17-20)
Bailey (WT3b, S18): no CER exists before award, so readiness "should theoretically always be pending"; "pre-approved" is a rare exception; "not approved" is really a recommendation to stop.
1. **Default when the quote enters Quoting** (every forward G2 decision, and a re-entry after a send-back if readiness is empty): Engineering's capital needed → `pending`; not needed (every item's figure entered and the quote's figure at or below `capital_needed_above_usd`) → `not_required`. Put the mapping in a new setting `capital_readiness_default` (`{ "whenNeeded": "pending", "whenNotNeeded": "not_required" }`, provisional) and read it in `gateService.ts`; leave `capital_readiness_on_outcome` working for the old outcome. Today's readiness upsert (`gateService.ts` ~703-718) writes **no** audit row of its own (the audit there is for `capital_likely`, and the `capital_needed` activity event fires only when capital is needed): add an audit row for the readiness default on both paths. The pricer can still change it.
2. **Open quotes already in Quoting** with no readiness: set the same default in the migration, following how `0031_fb07_costing_roi_price.sql` treated open quotes, with an audit row by the system actor. Leave every readiness someone has chosen untouched.
3. **The G3 rule. Ben decided (2026-11-18): "pending" is a normal capital state that needs no extra reasoning and never blocks a quote from moving forward.** Remove from `PRICE_APPROVED` both the `capital_likely = false OR readiness in (not_required, pre_approved)` rule **and** the "pending needs a justification" rule (`readiness in (…) OR capital_pending_justification present`). Change the seed and add a guarded `UPDATE` of `gate_outcome_definition.required_fields` for G3 `submit`, only where the row still holds the seeded rules and is unapproved. Keep "readiness present" (the default in step 1 always fills it). The justification box stays as an **optional** note: remove "Required while capital is still pending" and any server or domain check that demands it (`grep -rn "pending_justification\|pendingJustification"`).
4. **"Not approved" stops Advance.** Without the removed rule, `not_approved` would pass. Add a rule to G3 Advance: readiness is not `not_approved`, labelled "Capital is marked not approved: stop the quote, or change capital readiness". **Nothing later may block on `pending` either:** read `apps/api/src/services/final-review.ts`, the G4 rules and checks (`packages/domain/src/commercial/g4-checks.ts`), and the G5 / G6 rules; a pending-capital **warning** is fine, a blocker is not.
5. **Words.** In the Capital readiness card, under the status: "Pending is normal before award: no CER is raised until the customer awards the business. Pre-approved is an exception. Not approved means the quote should stop." Update the four status help texts in the same spirit (they are config if they live in a value list or setting: data migration, unedited and unapproved rows only). Keep "Not required" disabled with its hint when Engineering says capital is needed.
6. **Tests:** domain (the default mapping for $0, above 0, blank and multi-item), the G3 rule set (pending with no note passes; not approved fails with the new label; pre-approved and not required pass), the migration on a seeded and an empty database, an API integration test that walks a $20,000 synthetic quote from G2 to G3 Advance on `pending`, and one that cannot advance on `not_approved`. Playwright: the pricer sees "Capital pending" preselected and the lead advances.

### Part B. Payback only when someone asks Finance for it (N17-21, N17-22)
**Ben decided (2026-11-18):** a payback model is **not required for every quote**. The pricer or the pricing lead may **request** it from Finance; Finance is notified; when Finance uploads the payback model after a request, **whoever requested it is notified, and the pricing lead(s) are notified as they are today**. Bailey (WT3b 0:01-0:05) and Gemma (Demo 1:29) asked for the same.
1. **Record the request** on `pricing_record` (one per quote version): `payback_requested_by`, `payback_requested_at`, `payback_request_note` text (≤ 500, optional, shown to Finance), and `payback_request_withdrawn_at` / `_by` (with a short reason). Fabric-safe. Audited; timeline entries "Payback requested from Finance by <name>", "Payback request withdrawn: <reason>".
2. **Who may request or withdraw:** a new permission `payback.request`: **PricingLead**, and **Pricing on quotes assigned to them as pricer**. Matrix, `01-architecture.md` §3.4, route inventory, permission-matrix tests for every role. A request can be made once a costing model is on file and until G3 is decided; one open request at a time.
3. **What G3 needs** (replace the `roi_required` rule in `QUOTING_MODELS_ON_FILE`; change the seed and add a guarded `UPDATE`): a payback model is needed **only while an open request exists**; it is satisfied once Finance uploads one after the request. No request → no payback needed. Quotes already in Quoting that today need payback only because of `roi_required_when` stop needing it (say so in the PR). Rework `roi_required` / `roi_required_when` in `packages/domain/src/commercial/derived.ts` and `quoting-steps/index.ts` to follow the request, and update the lead-only fields in `lead-review/index.ts` to match; the pricer's submit check still ignores payback.
4. **`roi_required_when` becomes a hint**, not a rule: when it matches, the payback step says "Finance's payback model may be useful here: <reason>" beside the request button. Keep the setting and its seed; change its description to say it only suggests.
5. **Notices:**
   - **Request → Finance**: `quote.ready_for_roi` (existing event, `ROI_OWNER_ROLES = ['Finance']`), sent when the request is made, **not** on a costing upload any more. If no user holds Finance, say so on the step ("No one holds the Finance role, so no one was told") and in the PR; Stacy Slocum had no Finance role in the test environment, which is why nothing fired on Nov 17.
   - **Upload after a request → the requester and the pricing lead(s)**: keep `quote.roi_uploaded` going to every PricingLead as today (`notifications/recipients.ts` ~489-495) and **add** the user who made the open request (once, if they are also a PricingLead). A payback uploaded with no open request goes to the PricingLeads only, as today.
   - **Withdrawal → Finance**, so they stop work.
6. **UI** in "Costing, payback and price approval": the payback step reads "Not requested" by default (not "Waiting on an earlier step"); a user with `payback.request` sees **Ask Finance for a payback model** (optional note) and, while a request is open, **Withdraw request**. Everyone sees who asked, when, and whether Finance has uploaded. The price step no longer waits for payback unless a request is open.
7. **Tests:** domain (no request → G3 needs no payback; open request → it does until an upload after the request; withdrawn → it does not), permission matrix, API integration (Finance notified on request and not on a costing upload; the requester and every PricingLead notified on Finance's upload, the requester once even when they are a lead; a pricer and a lead can each request), Playwright (a pricer requests payback, Finance uploads, the pricer is notified, the lead approves; a second quote goes through with no request).
