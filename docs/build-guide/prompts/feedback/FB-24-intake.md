## What the code does today (read 2026-11-18 at `f017ccc`; verify before relying on it)
- **Ship-to:** only the Account's standard shipping address is read (`packages/integrations/src/salesforce/fieldMap.ts` ~63-71, selected as `Account.Shipping*` in `soql.ts` ~48-57; `mapper.ts` ~120-152). `fieldMap.ts` ~58-61 is a TODO (M3, D-18): the Account address is filled on 1,714 of 6,199 accounts (28 %); the org also has a **free-text** opportunity field `Ship_to_Locations__c` (55 % filled) and `Ship_To_City__c` / `Ship_To_State__c` on each product spec; none is mapped yet. With no address the full form shows empty (`Steps.tsx` ~188-200, ~299-322). City and state are required (`packages/db/seeds/config/settings.ts` ~59-60); a changed destination needs a reason.
- **Decoration type** is one code, `decorationType` (`contracts/intake.ts` ~101, `text(60)`), list `decoration_type` (Silk screen, Hot stamp, Shrink sleeve, Other with free text), shown only when the Decoration component is ticked, and required then (`Steps.tsx` ~794-809). Columns `quote.decoration_type` and `quote_item.decoration_type` (text), plus `decoration_type_other`.
- **Packaging type** list `packaging_type`: Bulk, Bagged, Trayed, Palletized-custom, Other. No "Soldier pack".
- **Item limits:** item `label` is 60 characters (contract `text(60)`, DB check `char_length(label) <= 60` in `0047`, form `maxLength={60}`, `Steps.tsx` ~1434); `standardDescription` is `text(500)` with no form limit (~1673-1678).
- **Attachments panel** (`components/attachments/Attachments.tsx`, shared by the intake and the quote's Attachments tab): a file-type dropdown built from every kind except the three Quoting models (`ATTACHMENT_KIND_VALUES.filter((k) => !isQuotingModelKind(k))`, ~237), so the intake offers 10 kinds, including Specification (`spec`), Capacity analysis, Equipment BOM and Offer letter. The server already refuses `offer_letter` everywhere and `equipment_bom` on a draft (`apps/api/src/services/attachments.ts` ~473-534); capacity analysis and specification are accepted. A second control, **"Add photo"** (`CameraIcon`, ~301-315), opens the camera / image picker (`accept="image/*" capture="environment"`) and forces kind `sample_photo`. Icons are `lucide-react`.
- **Dropdown order:** the API returns value lists in `value_list.sort` order (`packages/db/src/repos/config.ts` ~112-128); the intake's `Select` (`Steps.tsx` ~113-173) keeps that order. Engineering's `ValueListSelect` already sorts by label with Other last (`EngineeringTab.tsx` ~1715-1719, Bailey 2026-11-12).
- **Blocking vs warning:** intake `Notice` (`apps/web/src/intake/ui.tsx` ~49-77): `blocking` = red border on the card colour, `warning` = amber fill (`bg-warning`, `#f7d774`). The review step shows "Needed before you can submit" (blocking) and "Engineering may ask about this … You can still submit." (amber).
- **Returnable dunnage:** every path traced is consistent (checkbox `Steps.tsx` ~881, review row ~2166, contract default false, column `boolean NOT NULL DEFAULT false`); no bug found in code.
- **Items (FB-19):** `ItemsPanel` (`Steps.tsx` ~1230-1358: Add item, Add from Salesforce products, per-row Duplicate, Remove, Move) renders **above** the selected item's fields (~1888-1899), after the request-level sections.
- **Request class** list `request_class`: CCQ, Stock / stock-plus, Price inquiry / RFP check, Other capital. Only CCQ may be submitted (`INTAKE_ALLOWED_REQUEST_CLASSES`, `packages/db/seeds/config/settings.ts` ~77; `REQUEST_CLASS_NOT_ALLOWED`, `intake.ts` ~885-903). With no drawing, the minimum spec blocks (`DRAWING_OR_MIN_SPEC_REQUIRED`, `intake.ts` ~804-814; fields in `intake_min_spec_fields`: height, width or diameter, depth, gram weight, neck diameter and finish, resin, colour type). A drawing is a `bottle_drawing` or `competitor_drawing`.
- **Customer tooling commitment** is not asked at intake; it lives in the Commercial terms panel (`termsToolingCommitment`, Yes / No / not answered), editable by the KAM on their own quotes (`terms.edit`).
